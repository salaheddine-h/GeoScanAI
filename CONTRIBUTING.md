# Contributing to GeoScanAI

Thank you for investing your time in GeoScanAI. We welcome contributions that make land intelligence clearer, more reliable, and more accessible.

## Before you begin

- Review the [documentation hub](docs/README.md) and the relevant architecture or domain document.
- Search existing issues and pull requests before opening a new one.
- Read the [Code of Conduct](CODE_OF_CONDUCT.md) and [Security Policy](SECURITY.md).

## Contribution principles

- Keep each change focused on one clear outcome.
- Preserve module, domain, and data-boundary ownership unless the change explicitly proposes an evolution.
- Document assumptions, evidence sources, and important limitations.
- Prefer clear, maintainable structure over premature abstraction.
- Never commit secrets, tokens, private location data, or restricted datasets.

## Suggested workflow

1. Open an issue for substantial proposals so the direction can be discussed early.
2. Create a focused branch and make the smallest coherent change.
3. Update related documentation, diagrams, and links in the same pull request.
4. Run the relevant validation and confirm Markdown renders correctly on GitHub.
5. Open a pull request using the provided template and explain the user or platform impact.

## Documentation contributions

Documentation is a first-class part of GeoScanAI. Please keep headings descriptive, use relative links, avoid duplicated concepts, and place new material in the appropriate `docs/` area. Visual assets belong in `docs/images/` and should use clear, lowercase, hyphenated filenames.

## Pull request expectations

- Explain **what** changed and **why**.
- Include screenshots for visible documentation or interface changes when helpful.
- Keep unrelated formatting changes out of the pull request.
- Ensure no application logic, dependency, or runtime configuration changes were introduced unintentionally.

By contributing, you agree to follow the [Code of Conduct](CODE_OF_CONDUCT.md).
